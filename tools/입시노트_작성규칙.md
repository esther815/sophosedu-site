# 소포스 저널 — 기사 올리기 작업 지침 (새 채팅용)

> 원장님이 기사 링크만 보내면, 이 지침대로 정리해 **sophosedu.co.kr/brief.html**(소포스 저널)과
> 홈페이지 첫 화면의 '소포스 저널' 미리보기(최신 3건)에 올린다. 묻지 말고 끝까지 처리한 뒤 결과만 보고한다.

---

## 0. 한 번만 준비 (새 채팅을 열 때마다)

1. GitHub 저장소 **esther815/sophosedu-site** 를 붙인다(쓰기 권한 필요 → `add_repo` 에 `access: "push"`).
2. 저장소를 내려받고(clone) 그 폴더에서 작업한다.
3. 이 파일(`tools/입시노트_작성규칙.md`)을 처음부터 끝까지 읽는다.
4. 다른 채팅도 같은 저장소에 올리므로, **작업 시작 전과 올리기 직전에 반드시 `git pull --rebase`**.

## 0-1. 알림톡 발송 (중요)

- 이 기능이 켜진 뒤에는(`ALIMTALK_MODE=live`) **main 에 올리는 순간 재원생 구독 학부모께 카카오 알림톡이 나간다.** 되돌릴 수 없다.
- 그래서 원장님이 시안을 보고 「올려」라고 하기 전에는 절대 main 에 올리지 않는다.
- 알림톡에는 제목 · 세 줄 요약 · 소포스 노트가 그대로 들어간다(변수 치환 후 1,000자 이내). 오탈자는 올리기 전에 고친다.
- 이미 올린 기사를 고쳐도 알림톡은 다시 나가지 않는다(새 id 만 발송). 중대한 오류는 원장님께 바로 보고한다.
- 설정·준비 안내: `supabase/알림톡_준비_안내.md`

## 1. 손대는 파일 — 이것만

| 파일 | 하는 일 |
|---|---|
| `data/news.json` | 기사 목록. **여기에 한 건씩 추가만 한다.** |
| `tools/update_brief.py` | 실행하면 `brief.html`과 `index.html` 미리보기를 자동으로 다시 만든다. 검사도 해 준다. |
| `brief.html`, `index.html` | 위 스크립트가 만든다. **손으로 고치지 않는다.** |

그 밖의 파일(`member.html`, `director.html`, `lib/`, `vault/`, `img/` 등)은 절대 건드리지 않는다.

## 2. 한 건의 모양 (`data/news.json` 배열에 객체 하나 추가)

```json
{
  "id": "2611-20-csat-jeongsi",
  "date": "2026-11-20",
  "cat": "수능",
  "source": "한국일보",
  "url": "https://www.hankookilbo.com/news/article/A2026111913560005995",
  "title": "쉬운 수능, 정시 당락은 수학과 탐구가 가른다",
  "deck": "국어·영어 변별력이 약해지면서 수학·탐구가 핵심 변수로 떠올랐다. 재수생 규모와 사탐 선택 급증도 등급에 영향을 준다.",
  "points": [
    "입시업계는 국어·영어가 평이해 정시에서 수학과 탐구 성적의 비중이 커질 것으로 본다.",
    "올해 재수생 규모는 23년 만에 최대로, 상위권 경쟁이 더 촘촘해질 수 있다.",
    "사회탐구로 옮겨 간 수험생이 크게 늘어(이른바 사탐런) 과목별 유불리가 등급 결과를 좌우할 변수로 꼽힌다."
  ],
  "note": "가채점 점수는 실제 성적과 다를 수 있습니다. 12월 11일 성적 통지 전까지는 지원 대학의 영역별 반영 비율부터 확인해 두세요."
}
```

### 칸별 규칙
- **id**: `YYMM-DD-영문짧은말` (예: `2611-20-csat-jeongsi`). 기사 날짜 기준. 겹치면 끝에 `-2`.
- **date**: 기사 **게재일** `YYYY-MM-DD`. 오늘 날짜가 아니다. 요일은 자동 표시되므로 적지 않는다.
- **cat**: 다음 중 하나만 — `수능` · `논술` · `서·논술형` · `대입` · `고입` · `내신` · `교육정책`
  - 서·논술형 평가(학교 시험·수능 도입 논의) → `서·논술형`
  - 대학별 논술고사 일정·전략 → `논술`
  - 수능 난이도·등급컷·성적 → `수능` / 수시·정시·전형 → `대입`
  - 특목고·자사고·고교 배정 → `고입` / 5등급제·학교 시험 → `내신` / 정부·교육부 정책 일반 → `교육정책`
- **source**: 언론사 이름만(예: `한국경제`, `SBS`, `연합뉴스`). 기자 이름 쓰지 않는다.
- **url**: 원문 주소 그대로. 모바일 주소(`m.`)면 PC 주소로 바꿀 수 있으면 바꾼다. 추적용 꼬리(`?utm_...`)는 지운다.
- **title** (제목): **제목만 읽어도 무슨 일인지 알게** 쓴 한 문장. 28자 안팎.
  - 기사 제목을 베끼지 않고 새로 쓴다. 사실을 담는다(누가·무엇이·어떻게 됐다).
  - 물음표·느낌표·말줄임표·자극적 표현(충격, 비상, 대혼란 등) 금지.
- **deck** (한두 줄 풀이): 2문장, 합쳐서 90자 안팎. 제목을 보충하는 배경과 핵심.
- **points** (세 줄 요약): **정확히 3개**. 각 1문장, 70자 안팎. 기사에 있는 **사실**만, 내 말로 다시 쓴다.
  - 숫자·날짜·기관명은 기사와 똑같이. 확인 안 되면 넣지 않는다.
  - 전망·주장은 누구의 말인지 밝힌다("입시업계는 ~로 본다", "교육부는 ~할 계획이다").
- **note** (소포스 노트): 학부모가 **지금 할 일** 한두 문장. 존댓말("~하세요", "~입니다").
  - 사실이 아닌 해석·조언은 여기에만 쓴다. 과장·불안 조성·학원 홍보 문구 금지.
  - 날짜를 쓰면 반드시 공식 일정과 대조한다(예: 수능 성적 통지일).

## 3. 글쓰기 원칙 (반드시)

1. **저작권**: 기사 문장을 그대로 옮기지 않는다. 15단어 넘는 인용 금지, 한 기사에서 인용은 최대 한 번(되도록 0번). 문장 구조까지 바꿔 완전히 내 말로 쓴다.
2. **사실과 해석을 나눈다**: points = 기사 속 사실, note = 소포스의 조언.
3. **모르면 쓰지 않는다**: 기사에 없는 숫자·날짜·대학명을 지어내지 않는다. 검토·계획 단계면 "검토", "계획", "추진"으로 쓴다. 확정처럼 쓰지 않는다.
4. **말투**: 품위 있고 담백하게. 학부모가 처음 읽어도 아는 말로. 약어는 처음에 풀어 쓴다(예: 사회탐구(사탐)).
5. **한 기사 = 한 건**이 기본. 한 기사에 성격이 다른 두 주제가 뚜렷하면 두 건으로 나눌 수 있다(검사에서 '참고'로 알려 줌).
6. 정치적 입장·특정 대학/학원 비방·광고성 문구를 넣지 않는다.

## 4. 작업 순서

1. 원장님이 보낸 링크마다 기사를 연다(웹 읽기 도구). **열리지 않으면** 원장님께 "이 기사가 열리지 않습니다. 본문을 붙여 주세요"라고 한 줄로 요청하고, 나머지 기사는 계속 진행한다.
2. 이미 올라간 기사인지 `data/news.json`에서 url로 확인한다. 이미 있으면 건너뛰고 보고에 적는다.
3. 위 규칙대로 한 건씩 `data/news.json` 맨 앞에 추가한다(순서는 날짜로 자동 정렬되지만 맨 앞에 넣는다).
4. 저장소 맨 위 폴더에서 실행:
   ```bash
   git pull --rebase
   python3 tools/update_brief.py
   ```
   - "고칠 곳"이 나오면 고치고 다시 실행. "완료"가 나와야 다음으로.
5. 확인: `brief.html`을 열어 새 기사가 맨 위(날짜순)에 있고, 분류 칩으로 걸러지는지 본다. 가능하면 화면을 캡처해 본다(모바일 390px 너비 포함).
   - 줄 끝에 한두 글자만 남는 줄이 없는지 본다. 제목 끝 두 낱말은 자동으로 붙어 다니게 되어 있다. 그래도 어색하면 제목 낱말을 바꾼다.
6. 올리기:
   ```bash
   git add data/news.json brief.html index.html
   git commit -m "소포스 저널: (기사 제목 요약)"
   git pull --rebase && git push
   ```
   커밋 메시지 끝에는 그 채팅의 안내에 있는 Co-Authored-By 줄을 붙인다.
7. 1~2분 뒤 https://sophosedu.co.kr/brief.html 이 바뀌었는지 확인한다(못 열면 생략하고 보고에 적는다).

## 6. 참고 — 화면 구성 (바꾸지 말 것)

- 소포스 저널 페이지: 머리말 → '최근 세 줄'(최신 3건 제목) → 분류 칩·검색 → 기사 카드(분류·날짜·언론사 / 제목 / 풀이 / 세 줄 요약 / 소포스 노트 / 원문 기사 보기)
- 홈페이지 첫 화면 '소포스 저널' 칸: 최신 3건이 자동으로 바뀐다(`<!--BRIEF:START-->`~`<!--BRIEF:END-->` 사이를 스크립트가 교체).
- 디자인·분류 목록·페이지 구조를 바꾸려면 원장님 승인을 먼저 받는다. 분류를 새로 만들 때는 `tools/brief.py`의 `CATS`와 `tools/update_brief.py`의 `CATS`를 함께 고친다.
